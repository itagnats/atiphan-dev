# Atiphan — Portfolio

Personal portfolio site, built with **Next.js 16 (App Router)**, **React 19**, **TypeScript**, **Tailwind v4**, **Motion**, and **Lucide**.

## Setup (one-time)

Open a terminal in this folder (`D:\Personal\ita-dev-app`) and run:

```bash
npm install
```

This will install all dependencies into `node_modules/` (~ 1–2 min).

## Run locally

```bash
npm run dev
```

Then open <http://localhost:3000>.

## Routes

| Route | Description |
|---|---|
| `/` | Single-page portfolio — Hero, About, Work, Interactive Experiments, Experience, Leadership, Contact |
| `/cv` | Print-optimized resume (A4, two pages). The Download button serves `public/atiphan-charoenphon-cv.pdf` — see below. |
| `/work/[slug]` | **Disabled.** Case-study detail pages, kept on disk. See "Switched-off routes". |
| `/assignments/[slug]` | **Disabled.** One Young World material, kept on disk. See "Switched-off routes". |
| `/robots.txt`, `/sitemap.xml` | Generated by `app/robots.ts` and `app/sitemap.ts`. |

## Section numbering

`SectionHead` numbers run in page order and must stay in sync with both
`app/page.tsx` and `navItems` in `data/portfolio.ts`. All three have to agree —
they have drifted apart before, and `app/__tests__/page-structure.test.tsx` is
the guard that catches it.

| Order | Section | SectionHead | Nav id |
|---|---|---|---|
| 1 | Hero | — | `home` |
| 2 | About | `01 About` | `about` |
| 3 | Work | `02 Work` | `work` |

## The Work section

Two blocks.

**Featured Project — POCKITA.** The phone frame plays
`public/videos/pockita-demo.mp4` on a silent loop: muted, looping, no controls,
paused while off-screen, and replaced by a normal video with controls under
`prefers-reduced-motion`. The clip is encoded at 540×1156 to match the frame's
*content box* — `.phone-frame` is `border-box`, so its 8px border and 8px
padding both come out of the declared 260×520, leaving 228×488. **Change the
frame's size, border or padding in `globals.css` and the clip needs
re-encoding**, or `object-cover` starts clipping the edges.

**Selected Work — PRIME.** Five cards driven by `selectedWork` in
`data/portfolio.ts`, each expanding in place. These describe **PRIME, a personal
side project** — not employer work. They replaced four CP Group case studies on
2026-09-21.

> The provenance badge above the cards ("Personal project · Solo build") is
> load-bearing, not decoration. Without it the heading reads as employer work.
> Two tests in `data/__tests__/portfolio.test.ts` enforce this: one fails if the
> copy ever mentions CP Group or "our team", another if it claims active users.
> PRIME has a seeded demo dataset and no production traffic, so every figure in
> those write-ups is a seed count, a test count or a measured distribution.

A card with `wide: true` spans both grid columns. Only the design-system card
uses it.

## Switched-off routes

Two routes are kept on disk but unreachable. Both use the same mechanism:

```ts
export const dynamicParams = false;
export function generateStaticParams() { return []; }
```

**Both lines are required.** Returning `[]` alone still lets Next.js render the
page on demand at request time; `dynamicParams = false` is what turns an
unlisted slug into a 404.

- **`app/work/[slug]`** — disabled 2026-09-21. The case-study text was trimmed
  to overview / outcome / tech, which left a detail page holding less than the
  card linking to it, so everything moved onto the cards. Revival instructions
  are in a comment at the top of the file; `app/sitemap.ts` needs the `/work/*`
  entries put back too.
- **`app/assignments/[slug]`** — disabled 2026-09-01, when the site was rolled
  back from the CP Group **One Young World 2026** application (commit
  `293186a`). `assets/oyw-video.mp4` was moved out of `public/` so it is no
  longer served or deployed. `data/essay.md`, `ResumeContent.tsx`,
  `VideoContent.tsx` and the `assignments` / `oywResume` exports are retained
  and documented in place. The Leadership section was kept as a permanent part
  of the portfolio.

## The CV PDF

The Download button on `/cv` links to a **pre-generated file** at
`public/atiphan-charoenphon-cv.pdf`. It used to call `window.print()`, which
produced a different document per browser — margins, scale and the "background
graphics" setting all changed the result. A static file is the same for
everyone.

The current PDF came from a separate design pass (see `docs/cv-design-prompt.md`),
not from the `/cv` print stylesheet. It is a two-page A4 document whose text
extracts cleanly, which is what ATS parsers need.

The print stylesheet in `app/globals.css` still works if you would rather
regenerate from the page:

1. open `/cv`
2. print to PDF — A4, default margins, background graphics **off**
3. save over `public/atiphan-charoenphon-cv.pdf`

**Regenerate it whenever the CV content in `data/portfolio.ts` changes**, or the
download silently serves an old version. `tests/cv-pdf.test.ts` fails if the
file is missing entirely, but nothing can tell you it has gone stale.

## Tests

```bash
npm test          # Vitest, single run
npm run test:watch
```

Vitest + React Testing Library, jsdom environment. `vitest.setup.ts` stubs what
jsdom lacks and the components rely on: `IntersectionObserver`,
`Element.scrollTo`, `window.matchMedia`, and `HTMLMediaElement.play/pause`.

The suite guards the things TypeScript cannot:

- every `navItems` entry has a matching `<section id>`, and `SectionHead`
  numbers stay consecutive in rendered page order
- `selectedWork` slugs are unique and URL-safe
- the PRIME write-ups never claim employer attribution or production users
- `primeProject.repoUrl` is either empty or a well-formed GitHub URL — an empty
  string renders no link, which is the honest state while the repo is private
- the POCKITA video points at a real `.mp4` and carries a descriptive label
- the Work cards expand, collapse, and link nowhere (a stray `/work/...` link
  would now 404)
- the first-visit greeting fires once, then never again
- no placeholder text ("edit me", "goes here", "lorem") survives into the CV data

One test in `data/__tests__/portfolio.test.ts` is deliberately skipped: it
asserts leadership photo captions are more descriptive than "Photo 1". Unskip it
once real captions are written — the caption is also the image's alt text.

## Editing content

Almost all text lives in `data/portfolio.ts` — name, role, intro, bio, project
descriptions, experience entries, leadership events, contact links, astronaut
messages. Edit and save; the dev server hot-reloads.

`astronautMessages[0]` is special: it is the greeting the dialog opens itself
with on a first visit, so it should read as an introduction rather than a
mid-conversation aside. The "already greeted" flag is
`ita-dev:astronaut-greeted-v1` in `localStorage`; bump the version suffix in
`Navigation.tsx` to re-greet everyone.

## Deployment

```bash
npm i -g vercel
vercel
```

…or push to GitHub and import in the Vercel dashboard.

> **Set `NEXT_PUBLIC_SITE_URL` in the Vercel project settings.** `lib/site.ts`
> falls back to `http://localhost:3000`, and that fallback is silent — the build
> succeeds, but every Open Graph URL and every `sitemap.xml` entry then points
> at a machine nobody else can reach. Check `https://<your-domain>/sitemap.xml`
> after the first deploy; if it says `localhost`, the variable is missing.

## Build for production

```bash
npm run build
npm start
```
